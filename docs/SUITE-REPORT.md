# Deck suite — full corpus report (2026-10-25)

100 cases, one **new LibreChat conversation per case**, local `qwen3.6-27b`, rendering through the
`ppt` MCP server with the LibreOffice backend. Raw evidence: `tests/results/*.json` + `.md`.

## Result: 97/100 (97%), median 88 s

| category | pass | what it exercises |
|---|---|---|
| basics | **15/15** | plain decks, 2–8 slides |
| charts | **20/20** | column/bar/line/pie/doughnut/stacked, multi-series, two charts |
| tables | **12/12** | 3–8 rows, 4 columns, mixed with bullets |
| visuals | **10/10** | SVG diagrams generated by the model |
| stress | **12/12** | 10 slides, dense bullets, long titles, minimal |
| templates | **20/20** | Midnight, Ledger, Sandstone, Grid |
| mixed | 8/11 | chart + table + SVG in one deck |
| **total** | **97/100** | |

Plus a separate 10-case **random** set (topic × visual mix): 8/10.

## The three failures

| case | failure | prompt |
|---|---|---|
| `mixed-02` | table missing | 6-slide market entry plan with chart + table |
| `mixed-06` | table missing | 5-slide vendor selection with a table |
| `mixed-05` | 7 slides ≠ 6 | 6-slide research findings with chart + SVG |

Both classes are **model compliance**, not pipeline defects: the 27B describes the table in prose and
then omits the `table` object; and it occasionally counts the title slide as extra. Every code-level
defect found earlier in the project is now pinned by a regression test (35 unit tests + 7 browser checks).

## What the full run changed in the product

Instructions, not code, produced most of the gains — measured, not asserted:

| change | effect |
|---|---|
| "N slides means N−1 content slides" | slide-count drift: 2/10 → 1/100 |
| "use corporate-2slide unless a template is named" | stopped the model choosing Sandstone/Grid for "style fit" |
| "add a visual ONLY when asked; a bullet list that reads like a table is a FAILURE" | unrequested visuals 7/10 → 0; table-omission down to 2/100 |
| "check `visuals` in the result and rebuild once if something promised is missing" | recovered most omitted visuals |
| pass = artefact correct; tool errors are warnings | 0 tool-error runs in the final pass — the 27B self-corrects |

## Cost

88 s median × 100 ≈ **2 h 25 m** of local 27B time, no API spend. Slowest class: SVG authoring
(up to 315 s/case). Fastest: template decks (~70 s).

## Open work

1. **Table omission (2/100)** — the last recurring model failure. Next lever is mechanical: have
   `build_deck` return `requested_visuals` vs `rendered_visuals` and let the agent retry on a diff, or
   make the runner re-drive those cases.
2. **Slide-count drift (1/100)** — cheap guard: the agent could assert `slide_count` against the ask.
3. Per-run emphasis in the pane (bold a phrase) exists as `style_text`; a text-selection UI is not built.
4. Renderer: portable LibreOffice is the chosen Windows path; Aspose remains the paid alternative.

## Addendum — the three failures fixed (2026-10-25, later)

Root cause found while writing a test for `verify_deck`: **a slide spec carrying both `chart` and
`table` silently kept only the chart.** That is how a deck could "include a table" and ship without
one. `build_deck` now rejects multiple visuals on one slide with an explicit message ("one visual per
slide — split them"), and a new `verify_deck(file, expected_slides, table, chart, image)` gives the
agent a hard signal with a `problems` list to act on.

Re-ran the three failures plus eight new regression cases:

| set | result | median |
|---|---|---|
| `mixed-02`, `mixed-05`, `mixed-06` | **3/3 pass** | 107 s |
| `regress-01 … regress-08` (new) | **8/8 pass** | 101 s |

All 11 runs called `verify_deck`; five of them used the retry loop (`build → verify → build → verify`),
i.e. the safety net caught a real defect and the model corrected it.

### Concurrency

`tests/concurrency_check.py` drives the live HTTP server with parallel MCP clients: 4 distinct decks +
2 clients on the same deck → **6/6 renders ok**, every deck reporting all 6 slides rendered. Repeatable
by any operator; the same properties are covered in CI by three threaded unit tests (parallel builds,
same-deck renders, interleaved style+render).
